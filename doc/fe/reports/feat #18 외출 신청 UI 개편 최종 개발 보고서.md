## 구현 요약

학생 외출 신청 화면을 현재 디자인 시스템에 맞춰 정리하고, 신청 목록·상세·수정·개별 취소까지 이어지는 UI 흐름을 구현했습니다. 반복적으로 발생한 입력 및 화면 전환 크래시를 피하기 위해 학생 신청·수정은 UI 프리뷰 상태에서 동작하도록 분리했습니다.

## 구현된 기능

- [x] 학생 외출 랜딩·신청 폼·신청 목록·상세 화면 UI
- [x] 이번 주 범위의 한글 달력과 외출 날짜 선택
- [x] 점심(12:30~13:30), 저녁(18:10~19:10), 직접 시간 설정
- [x] 담당 선생님 검색·선택 및 외출 사유 3줄 입력 UI
- [x] 신청 후 목록 카드 즉시 추가 및 목록 화면 전환
- [x] 신청 상세의 수정 버튼·`외출 수정` 제출 버튼
- [x] 신청 건별 취소 확인 및 선택한 카드만 제거
- [x] 교사용 승인 요청 목록·상세·수락·거절 사유 UI
- [x] 상태 필터, 카드 배지, 상세 화면 레이아웃 개선

## 계획서 대비 변경 사항

| 항목 | 계획 | 실제 구현 | 사유 |
|---|---|---|---|
| 학생 신청 저장 | Repository 제출 및 검증 | UI 프리뷰 상태에 즉시 추가 | 입력 처리·화면 전환 중 발생한 UIKit 크래시를 분리하고 UI 검토를 우선하기 위함 |
| 학생 신청 취소·수정 | Repository 갱신 | UI 프리뷰 배열의 해당 ID만 갱신·삭제 | 여러 신청 카드의 개별 상태를 안전하게 확인하기 위함 |
| 사유 입력 | `TextEditor` | 3줄 다중행 `TextField` | `NSConcreteMutableAttributedString` 관련 입력 경로를 피하고 한글 입력 안정성을 높이기 위함 |

## 발견 이슈 및 조치

| 이슈 | 심각도 | 조치 |
|---|---|---|
| 신청 입력값이 화면과 다르게 검증되어 신청 차단 | Major | 학생 신청을 UI 프리뷰 흐름으로 분리 |
| 신청·수정 완료 시 중복 화면 전환으로 크래시 발생 | Critical | 수정 후 부모·자식의 이중 네비게이션 상태 변경 제거 |
| 한글 입력 중 `NSConcreteMutableAttributedString` 예외 | Critical | 학생 외출 사유 `TextEditor` 제거 및 다중행 `TextField` 적용 |

## 알려진 제한사항

- 학생 신청·수정·취소는 UI 검토용 메모리 상태이며 앱 재실행 시 초기화됩니다.
- 실제 외출 API, 인증 권한, 선생님 검색 API와의 연동은 후속 작업이 필요합니다.
- UIKit 예외는 실기기와 대상 iOS 버전에서 재현·검증이 추가로 필요합니다.
