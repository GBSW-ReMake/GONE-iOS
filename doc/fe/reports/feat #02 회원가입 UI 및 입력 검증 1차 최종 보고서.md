## 구현 요약

로그인 화면에서 진입하는 회원가입 UI를 SwiftUI MVVM 구조로 구현했습니다. 회원가입은 아이디 → 비밀번호 확인 → 전화번호 인증 순서의 3단계 흐름이며, 기존 GONE 디자인 시스템과 동일한 폼·CTA·SF Pro 기준을 사용합니다.

## 구현된 기능

- [x] 로그인 `회원가입` 링크와 회원가입 화면 전환 연결
- [x] 아이디 → 비밀번호 확인 → 전화번호·인증번호 입력의 3단계 UI
- [x] 단계 진행 표시, 화면·단계 전환 애니메이션, 뒤로가기 동작
- [x] 비밀번호와 확인 값이 일치할 때만 다음 CTA 활성화
- [x] 전화번호 숫자 입력 시 하이픈 포맷 적용
- [x] 글래스 스타일 뒤로가기 버튼과 테두리형 인증번호 받기 버튼
- [x] 라이트·다크 모드에서 고정 대비를 유지하는 뒤로가기·인증번호 버튼
- [x] `SignupViewModel` 분리 및 단계·비밀번호·전화번호 포맷 단위 테스트
- [x] 기본 AppIcon 에셋 등록
- [ ] 아이디 중복 확인, 인증번호 발송·검증, 실제 회원가입 요청 (API 계약 미확정)

## 계획서 대비 변경 사항

| 항목 | 계획 | 실제 구현 | 사유 |
|---|---|---|---|
| 가입 순서 | 전화번호 인증 중심 초안 | 아이디 → 비밀번호 → 전화번호 인증 | 개발자 검토 의견 반영 |
| 전화번호 포맷 | 입력 폼 | 하이픈 자동 포맷 | 입력 가독성 개선 |
| 화면 전환 | 기본 화면 전환 | 슬라이드·투명도 애니메이션 | 실기기 UX 검토 반영 |
| 버튼 표현 | 기본 버튼 | 글래스 뒤로가기·고정 대비 테두리 버튼 | 다크 모드 실기기 QA 반영 |
| 인증 API | API 명세 기반 연동 | 미구현 | endpoint·DTO·인증 정책 미확정 |

## 알려진 제한사항

- Notion API 명세 접근 권한이 없어 실제 인증번호 발송·검증과 회원가입 요청을 연결하지 않았습니다.
- 아이디 중복 확인, 비밀번호 정책, 인증번호 만료·재발송 정책, 가입 성공 후 목적지는 API 계약 확인 후 구현합니다.
- iOS 26 AppIcon의 다크·틴티드 변형은 별도 디자인 에셋이 제공되면 추가합니다.
