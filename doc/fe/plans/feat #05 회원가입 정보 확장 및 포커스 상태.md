## 1. 목적 및 배경

기존 회원가입 흐름에 학생 식별 정보와 프로필 사진 설정을 추가합니다. 사용자는 아이디·비밀번호·전화번호 인증 이후 학번과 이름을 각각 입력하고, 선택적으로 프로필 사진을 설정한 뒤 가입을 시작합니다.

또한 공통 밑줄 입력 폼에서 포커스가 생길 때 밑줄뿐 아니라 입력 항목의 제목(예: `아이디`, `비밀번호`)도 메인 컬러로 표시해 현재 입력 위치를 더 명확히 알립니다.

## 2. 사용자 시나리오

```text
사용자가 회원가입을 시작한다
→ 아이디를 입력한다
→ 비밀번호와 비밀번호 확인을 설정한다
→ 전화번호 인증을 완료한다
→ 학번을 입력한다
→ 이름을 입력한다
→ 필요하면 사진 보관함에서 프로필 사진을 선택한다
→ 사진을 선택하지 않아도 가입 시작 CTA를 누를 수 있다
→ 가입 요청 API가 연결되기 전에는 기존 안내 메시지로 상태를 알린다
```

## 3. 화면 및 UX

### 화면 구성

- 진행 단계는 총 5단계로 표시합니다.
  1. 아이디
  2. 비밀번호
  3. 전화번호 인증
  4. 학번·이름
  5. 프로필 사진
- 학번·이름 단계
  - 제목: `학번 이름을 입력해주세요`
  - 설명: `학번 이름을 입력해 주세요.`
  - `학번`과 `이름`을 각각 별도의 밑줄 입력 폼으로 제공합니다.
  - 학번 placeholder는 `1101`, 이름 placeholder는 `홍길동`을 사용합니다.
  - 두 입력값에서 공백을 정리한 결과가 모두 비어 있지 않을 때만 `다음` CTA를 활성화합니다.
- 프로필 사진 단계
  - 제목: `프로필 사진을 설정해주세요`
  - 설명: `나중에 언제든지 바꿀 수 있어요.`
  - 기본 프로필 이미지를 표시하고, 사진 선택 버튼으로 iOS 사진 선택기를 엽니다.
  - 선택한 사진은 원형 미리보기로 표시합니다.
  - 사진 선택은 선택 사항이며, 사진이 없어도 `시작하기` CTA를 활성화합니다.
- 공통 밑줄 입력 폼
  - 포커스 상태: 밑줄과 라벨을 `Color.goneBrandPrimary`로 변경합니다.
  - 오류 상태: 포커스보다 오류 상태를 우선해 밑줄과 라벨을 `Color.goneStatusError`로 표시합니다.
  - 비포커스/정상 상태: 기존 보조 텍스트 컬러와 기본 밑줄 컬러를 유지합니다.

### 상태 및 예외 처리

- 학번·이름: 학번 또는 이름이 비어 있으면 해당 폼에 오류 문구를 표시하고 같은 단계에 머무릅니다.
- 프로필 사진: 사진 라이브러리 접근을 거부하거나 사진 읽기에 실패하면 사용자가 사진 없이 계속 가입할 수 있도록 안내합니다.
- 사진 선택 중: 선택 버튼은 중복 실행을 방지하고, 완료/취소 후 원래 상태로 복귀합니다.
- 가입 요청: 현재 API 계약이 없으므로 기존 서비스 연결 안내를 유지하며, 실제 업로드·가입 호출은 API 명세 확정 후 연결합니다.

### 접근성

- 진행 표시의 전체 단계 수를 5로 갱신해 VoiceOver에 전달합니다.
- 사진 선택 버튼은 `프로필 사진 선택` 레이블과 선택 사항임을 안내합니다.
- 사진 미리보기에는 선택 여부를 포함한 접근성 값을 제공합니다.
- 사진 선택 버튼과 하단 CTA는 최소 44pt 터치 영역을 유지합니다.
- 라벨의 포커스·오류 표현은 색상뿐 아니라 VoiceOver 및 오류 텍스트로도 식별 가능하게 합니다.

## 4. 데이터 및 아키텍처

### 데이터 흐름

```text
SignupView
→ SignupViewModel
→ SignupDraft (identifier, password, phoneNumber, studentNumber, name, profileImageData)
→ SignupUseCase / AuthRepository (API 계약 확정 후)
```

- `SignupView`: 단계별 UI, `PhotosPicker` 표시, 사용자 입력 이벤트 전달만 담당합니다.
- `SignupViewModel`: 현재 단계, 학번·이름의 독립 문자열과 오류 상태, 선택한 프로필 이미지 데이터, 입력 유효성을 관리합니다.
- `SignupDraft`: 가입 요청에 필요한 입력값을 한곳에 모을 수 있도록 필요 시 도입합니다. 이번 변경은 API 계약 범위에 따라 과도한 계층 추가를 피합니다.
- `GONEUnderlinedTextField`: 포커스/오류에 따른 라벨 색상만 공통으로 처리합니다.

### 외부 의존성 및 결정 필요 항목

- 회원가입 API의 학생 정보 필드 구조(학번·이름 필드명, 형식·길이 정책)
- 프로필 이미지 업로드 방식(이미지 파일 endpoint, 허용 형식·용량, 기본 이미지 처리)
- 전화번호 인증 완료 여부를 실제 가입 요청에 포함하는 API 계약
- 프로필 사진 단계의 가입 성공 후 이동 목적지
- Figma MCP 호출 한도 때문에 제공된 파일의 원본 노드는 이번 계획 시점에 직접 조회하지 못했습니다. 첨부된 화면과 기존 디자인 토큰을 구현 기준으로 사용하며, 한도 해제 후 원본 노드 대조가 필요합니다.

## 6. 완료 기준

- [ ] 회원가입 단계가 아이디 → 비밀번호 → 전화번호 인증 → 학번·이름 → 프로필 사진 순서로 동작한다.
- [ ] 학번과 이름 중 하나라도 비어 있으면 다음으로 진행할 수 없으며, 둘 다 입력하면 CTA가 활성화된다.
- [ ] 프로필 사진을 선택하지 않아도 시작하기 CTA로 가입 흐름을 완료할 수 있다.
- [ ] 선택한 사진은 원형 미리보기로 표시되고, 취소·권한 거부·읽기 실패 시 가입 흐름이 막히지 않는다.
- [ ] 포커스된 입력 폼의 라벨과 밑줄이 메인 컬러로 표시되며, 오류 상태는 오류 컬러가 우선한다.
- [ ] VoiceOver, Dynamic Type, 다크 모드 및 최소 터치 영역을 확인한다.
- [ ] 기존 `SignupViewModelTests`와 신규 상태 테스트가 통과한다.

## 7. 특이 사항 / 기술 검토

- 현재 작업 트리에 실습실 예약 및 에셋 관련 미커밋 변경이 존재합니다. 이 기능에서는 해당 변경을 수정하거나 커밋에 포함하지 않습니다.
- 기존 회원가입 기능 브랜치와 구분되는 후속 기능으로 별도 이슈·브랜치를 사용합니다.
- 사용자 요청에 따라 프로필 사진은 선택 사항으로 처리합니다. API 명세 전에는 이미지 업로드를 임의로 구현하지 않습니다.
