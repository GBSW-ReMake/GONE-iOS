## 1. 목적 및 배경

현재 외출 신청 화면은 신청 전 랜딩 화면과 신청 후 상태 화면의 시각적 흐름이 분리되어 있고, 신청 폼의 시간 선택 방식이 한 화면에 모두 노출되어 입력 단계가 길어졌습니다.

이번 개편에서는 교사 외출 신청 목록에서 사용하는 카드 스타일과 동일한 정보 계층을 학생 화면에도 적용합니다. 신청 전에는 기존 안내·이미지·신청 CTA를 유지하고, 신청 후에는 이미지를 숨긴 뒤 외출 신청 카드 목록으로 전환합니다. 시간 선택은 점심·저녁·직접 시간 설정 중 하나를 선택하도록 단순화하고, 직접 설정을 선택했을 때만 시간 입력 영역이 자연스럽게 펼쳐지도록 개선합니다.

## 2. 사용자 시나리오

```text
[신청 전]
학생이 외출 탭에 진입한다
→ 기존 외출 안내 제목과 설명, 외출 이미지를 확인한다
→ 외출 신청 CTA를 누른다

[신청 후]
신청을 완료하거나 기존 신청이 있으면
→ 기존 중앙 이미지를 숨긴다
→ 학생 외출 신청 카드 목록을 표시한다
→ 카드에서 상태, 날짜, 시간, 사유, 담당 선생님을 확인한다
→ 외출 신청 CTA로 추가 신청을 시작한다

[시간 설정]
신청 폼에서 점심·저녁·직접 시간 설정 중 하나를 선택한다
→ 점심 또는 저녁 선택 시 해당 프리셋 시간이 즉시 반영된다
→ 직접 시간 설정 선택 시 시간 입력 영역이 애니메이션과 함께 펼쳐진다
→ 출발·복귀 시간은 08:40~20:30 범위에서만 선택한다
```

## 3. 화면 및 UX

### 학생 외출 기본 화면

- 상단 제목은 기존 흐름처럼 `외출`을 유지합니다.
- 신청 전 상태:
  - 기존 외출 신청 제목과 안내 문구 유지
  - 기존 외출 이미지 유지
  - 하단 `외출 신청` CTA 유지
- 신청 후 상태:
  - 외출 이미지를 제거합니다.
  - 교사 신청 목록과 동일한 카드 스타일의 학생 신청 목록을 표시합니다.
  - 카드에는 상태 배지, 날짜, 출발·복귀 시간, 외출 사유, 담당 선생님을 표시합니다.
  - 여러 건의 신청을 세로 목록으로 보여주며, 카드 간 간격과 화면 양옆 패딩을 일정하게 유지합니다.
  - 목록 하단 또는 상단의 `외출 신청` CTA로 추가 신청을 시작합니다.

### 학생 외출 카드

- 정보 순서: 상태 배지 → 날짜 → 외출 시간 → 외출 사유 → 담당 선생님
- 교사 목록에서 사용한 카드의 모서리, 배경, 상태 색상, 좌우 패딩을 재사용합니다.
- 승인 상태는 텍스트와 색상을 함께 사용합니다.
  - `승인 요청`
  - `승인 완료`
  - `거절됨`
- 신청 취소는 승인 요청 상태에서만 노출하고, 터치 영역은 44pt 이상으로 유지합니다.

### 신청 폼

- 기존 신청 폼의 제목, 안내 배너, 날짜, 선생님 검색, 사유 입력 흐름은 유지하되 시각적 간격과 계층을 카드 스타일과 맞춥니다.
- 시간 설정 영역은 다음 3개 선택지 중 하나를 선택하는 단일 선택 UI로 변경합니다.
  - `점심`
  - `저녁`
  - `직접 시간 설정`
- 선택된 항목은 GONE 메인 컬러의 선택 상태로 표현합니다.
- 점심·저녁을 선택하면 프리셋 출발·복귀 시간이 즉시 반영됩니다.
- 직접 시간 설정을 선택한 경우에만 출발·복귀 시간 입력 컨테이너가 아래로 펼쳐집니다.
- 펼침·접힘은 SwiftUI transition/animation으로 처리하고, 레이아웃이 갑자기 밀리지 않도록 자연스러운 높이 변화를 사용합니다.
- 직접 시간 설정의 DatePicker 범위는 `08:40...20:30`으로 제한합니다.
- 복귀 시간은 출발 시간보다 늦어야 하며, 범위·중복 검증 오류는 입력 영역 가까이에 표시합니다.
- 필수 입력 전 `외출 신청하기` 버튼은 기존 디자인처럼 연한 파란색 비활성 상태로 표시합니다.
- 날짜·시간·사유·담당 선생님이 모두 유효해지면 버튼을 GONE 메인 파란색 활성 상태로 전환합니다.

### 접근성 및 상태

- 선택된 시간 모드는 VoiceOver에서 선택 상태를 전달합니다.
- 직접 설정 영역의 펼침 상태와 입력 가능 여부를 접근성 요소에 반영합니다.
- 로딩, 신청 없음, 신청 실패, 잘못된 시간, 중복 시간 상태를 기존 오류 안내 스타일로 통일합니다.
- Dynamic Type에서 카드와 선택 컨트롤이 겹치지 않도록 긴 텍스트 줄바꿈을 허용합니다.

## 4. 데이터 및 아키텍처

### 데이터 흐름

```text
OutingView
→ StudentOutingListView / OutingLandingView
→ OutingRequestForm
→ OutingViewModel
→ OutingDraft / OutingRepository
```

- `OutingView`: 신청 전/신청 후 상태에 따라 랜딩 또는 카드 목록을 선택합니다.
- `OutingRequestForm`: 시간 모드 선택, 직접 시간 영역 펼침 상태, 입력 UI를 관리합니다.
- `OutingDraft`: 선택된 시간 모드와 실제 출발·복귀 시간을 표현합니다.
- `OutingViewModel`: 기존 신청 목록, 신청 제출, 취소, 오류·로딩 상태를 유지합니다.
- `OutingRepository`: 시간 정책 검증은 기존 계약을 유지하고, 실제 API 연동 시 서버 검증과 동일하게 맞춥니다.

### 검증 규칙

- 신청 가능 날짜: 현재 주 내
- 외출 가능 시간: 08:40~20:30
- 복귀 시간: 출발 시간 이후
- 중복 시간: 같은 날짜의 기존 미취소·미거절 신청과 겹치지 않음
- 학생 사유 및 담당 선생님 필수

## 5. 작업 목록

- [ ] 신청 전 랜딩 화면의 기존 제목·설명·이미지·CTA를 기준 화면으로 정리한다.
- [ ] 신청 후 중앙 이미지를 제거하고 카드 목록 상태로 전환한다.
- [ ] 학생 신청 카드의 정보 순서와 스타일을 교사 목록 카드와 통일한다.
- [ ] 시간 설정을 점심·저녁·직접 시간 설정 3개 선택 UI로 변경한다.
- [ ] 직접 시간 설정 선택 시 시간 입력 컨테이너의 펼침 애니메이션을 구현한다.
- [ ] 직접 시간 입력 범위를 08:40~20:30으로 제한한다.
- [ ] 입력 전 신청 버튼을 연한 파란색 비활성 상태로 표시하고, 유효 입력 후 메인 파란색으로 활성화한다.
- [ ] 기존 중복·기간·사유·담당 선생님 검증 회귀 여부를 확인한다.
- [ ] 학생 신청 전·후, 추가 신청, 오류·빈 상태 QA를 진행한다.

## 6. 완료 기준

- [ ] 신청 전에는 기존 제목·안내·이미지·CTA 화면이 유지된다.
- [ ] 신청 후에는 이미지가 사라지고 카드 목록이 표시된다.
- [ ] 카드 정보 순서가 상태 → 날짜 → 시간 → 사유 → 담당 선생님으로 일관된다.
- [ ] 시간 모드 3개 중 하나만 선택할 수 있다.
- [ ] 점심·저녁 선택 시 프리셋 시간이 반영된다.
- [ ] 직접 시간 설정 선택 시 입력 영역이 애니메이션으로 펼쳐진다.
- [ ] 직접 시간은 08:40 이전 또는 20:30 이후로 설정할 수 없다.
- [ ] 기존 신청 검증과 교사 검색·선택 기능이 회귀하지 않는다.
- [ ] 정적 검사와 시뮬레이터 화면 QA 결과가 기록된다.

## 7. 결정 필요 사항

- 점심·저녁 프리셋의 정확한 시작·종료 시간
- 신청 후 `외출 신청` CTA의 위치(목록 상단 또는 하단)
- 신청 카드에서 사유 전문을 표시할지, 요약 후 상세에서 표시할지
- 직접 시간 설정 DatePicker의 분 단위 간격(1분 또는 5분)
