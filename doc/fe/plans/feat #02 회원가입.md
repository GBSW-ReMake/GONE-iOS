## 1. 목적 및 배경

GONE을 처음 사용하는 학생이 이메일 인증과 비밀번호 설정을 거쳐 계정을 만들 수 있는 회원가입 흐름을 제공합니다.

회원가입은 로그인 화면의 `회원가입` 링크에서 진입하는 독립 기능입니다. 로그인과 동일한 공용 디자인 시스템·폰트·입력 폼을 재사용해 화면 간 일관성을 유지합니다.

## 2. 사용자 시나리오

```text
사용자가 로그인 화면에서 회원가입을 누른다
→ 이메일을 입력하고 인증번호 발송을 요청한다
→ 인증번호를 입력해 이메일 인증을 완료한다
→ 비밀번호와 비밀번호 확인을 입력한다
→ 가입 정보를 제출한다
→ 가입 성공 시 로그인 화면 또는 인증 완료 목적지로 이동한다
→ 입력·인증·네트워크 오류가 발생하면 원인을 확인하고 다시 시도한다
```

- 공통 구성: 뒤로가기, 중앙 GONE 로고, 3단계 진행 표시, 제목·설명, 입력 폼, 하단 CTA
- 이메일 단계: 이메일 입력, 인증번호 발송 버튼, 인증번호 입력, 인증 상태·오류 메시지
- 비밀번호 단계: 비밀번호·비밀번호 확인 입력, 일치 여부 안내, 가입 완료 CTA
- 마지막 진행 단계의 상세 입력 항목과 가입 완료 목적지는 피그마·API 명세 확인 후 확정합니다.

### 로그인 화면과 공통 디자인 기준

- 좌우 여백: 24pt, CTA: 높이 54pt·모서리 반경 16pt, 터치 영역: 최소 44pt
- SF Pro: 로고 29pt, 제목 23pt, 설명 15pt, 폼 라벨 13pt, 입력값 17pt, CTA 17pt
- `GONEUnderlinedTextField`, `GONEPrimaryButton`, `GONEFont`, 색상 토큰을 재사용합니다.
- 입력 안내·오류 문구는 라이트·다크 모드에서 대비가 유지되는 GONE 색상 토큰을 사용하고, 폼 바로 아래 왼쪽에 표시합니다.

### 상태

- 이메일 입력 전: 다음 CTA 비활성화
- 인증번호 발송 중: 발송 버튼 중복 요청 방지 및 로딩 표시
- 인증번호 입력: 만료·불일치·성공 상태를 텍스트와 색상으로 안내
- 비밀번호 입력: 비어 있음·형식 오류·불일치 상태 표시
- 가입 요청 중: 최종 CTA 로딩과 중복 제출 방지
- 가입 성공: 명세에 따른 다음 화면 전환
- 네트워크·서버 오류: 재시도 가능한 안내 제공

### 접근성

- 진행 단계는 현재 단계와 전체 단계 수를 VoiceOver에 전달합니다.
- 뒤로가기·인증번호 발송·다음 CTA는 각각 44pt 이상의 독립 터치 영역을 갖습니다.
- 인증 성공·실패·비밀번호 불일치는 색상뿐 아니라 텍스트로도 전달합니다.
- Dynamic Type 확대 시 폼과 하단 CTA가 겹치지 않도록 스크롤 가능한 레이아웃을 사용합니다.

## 4. 데이터 및 아키텍처

### 데이터 흐름

```text
SignupFlowView
→ SignupViewModel
→ SendEmailVerificationUseCase / VerifyEmailUseCase / SignupUseCase
→ AuthRepository (protocol)
→ RemoteAuthRepository / APIClient
→ 인증·회원가입 API
```

- `SignupFlowView`: 단계별 UI와 이벤트 전달을 담당합니다.
- `SignupViewModel`: 현재 단계, 입력값, 유효성, 인증 타이머, 로딩·오류 상태를 관리합니다.
- UseCase: 이메일 발송·인증·가입 완료의 비즈니스 흐름을 분리합니다.
- `AuthRepository`: 인증 API 접근을 추상화합니다.
- DTO와 실제 네트워크 구현은 API 계약 확인 후 Data 계층에 추가합니다.

### 외부 의존성 및 결정 필요 항목

현재 Notion API 명세에 접근할 수 없어 다음 항목은 추정 구현하지 않습니다.

- 이메일 인증번호 발송·확인·재발송 endpoint와 요청/응답 DTO
- 인증번호 만료 시간, 재발송 제한, 실패 횟수 정책
- 가입 요청 필드(이메일 외 학생 정보·약관 동의·프로필 정보 포함 여부)
- 비밀번호 정책과 서버 오류 코드·메시지
- 가입 성공 후 자동 로그인 여부와 이동 목적지
- 피그마 3단계 중 마지막 단계의 상세 UI와 입력 항목

## 7. 특이 사항 / 기술 검토

- 회원가입은 로그인 #01과 별도 이슈·브랜치·PR로 진행합니다.
- 기능 브랜치는 ASCII 영문 소문자 케밥 표기법인 `feat/<이슈번호>-signup`을 사용합니다.
- PR은 `dev` 대상으로 Ready for review 상태로 생성합니다. 개발자가 명시적으로 요청하기 전에는 `main` 대상 PR을 생성하지 않습니다.
- API 계약 또는 피그마 마지막 단계가 확정되기 전에는 입력 필드·DTO·인증 정책을 임의로 추가하지 않습니다.
