## 1. 목적 및 배경

학생·선생님이 역할에 맞는 알림을 확인할 수 있도록 알림 화면을 추가하고, 홈 화면 헤더와 주요 섹션을 제공된 GONE 로고·벨·3D 일러스트 에셋 기준으로 개선한다.

학생 알림은 본인 활동의 결과(스쿨캠핑, 외출, 상벌점, 실습실 등)를 보여주고, 선생님 알림은 학생의 신청·예약 발생을 보여주는 형태로 구분한다. 현재 API가 확정되지 않았으므로 Mock Repository 기반으로 UI 및 상태 흐름을 구현한다.

## 2. 사용자 시나리오

### 학생

```text
학생이 홈 화면에 진입한다
→ 헤더의 알림 버튼을 누른다
→ 오늘/어제/최근 7일로 구분된 본인 알림을 확인한다
→ 모두 읽음을 누르면 미읽음 상태가 해제된다
→ 뒤로 가기를 누르면 홈으로 돌아온다
```

### 선생님

```text
선생님이 홈 화면에 진입한다
→ 헤더의 알림 버튼을 누른다
→ 오늘/어제/최근 7일로 구분된 학생 신청 알림을 확인한다
→ 학생명, 학급·인원·시간 등 신청 맥락을 확인한다
→ 모두 읽음을 누르면 미읽음 상태가 해제된다
```

## 3. 화면 및 UX

### 화면 구성

- 홈: 기존 날짜/인사 문구를 제거하고 GONE 로고를 좌측, 알림 버튼을 우측에 배치한다.
- 홈 섹션: 시간표, 급식, 학사일정, 신청현황 타이틀에 제공된 3D 아이콘을 적용한다.
- 알림: 공통 `NotificationView`를 사용하며 `AccountRole`에 따라 학생용/선생님용 목록을 표시한다.
- 알림 헤더: 뒤로 가기, 중앙의 “알림”, 우측의 “모두 읽음”을 제공한다.
- 알림 목록: “오늘”, “어제”, “최근 7일” 섹션과 아이콘·제목·설명·상대/절대 시간을 제공한다.

### 상태

- 정상: 역할에 맞는 알림 목록 표시
- 로딩: `ProgressView` 표시
- 빈 상태: “새로운 알림이 없어요” 표시
- 오류: 재시도 버튼을 포함한 오류 안내
- 읽음 처리: 모두 읽음 실행 후 읽음 상태 반영 및 버튼 접근성 상태 갱신

### 접근성

- 알림 버튼에 “알림” 레이블과 미읽음 개수 힌트를 제공한다.
- 알림 행은 제목·설명·시간을 하나의 읽기 단위로 묶는다.
- 아이콘은 장식 요소로 숨기고, 동적 글자 크기에서 텍스트가 잘리지 않도록 유연한 레이아웃을 사용한다.
- 버튼 터치 영역은 최소 44pt를 보장한다.

## 4. 데이터 및 아키텍처

### 데이터 흐름

- API / Repository: `NotificationRepository` 프로토콜과 `MockNotificationRepository`
- UseCase: `FetchNotificationsUseCase`, `MarkAllNotificationsReadUseCase`
- ViewModel 상태: `loading`, `loaded`, `empty`, `failed`, 읽음 처리 상태
- Model: 역할, 알림 종류, 제목, 설명, 생성일, 읽음 여부를 포함하는 `Notification`
- 화면 진입: `AppTabView`가 `NavigationStack`으로 홈과 알림을 연결한다.

### 외부 의존성 및 결정 필요 항목

- 실제 API 응답·푸시 수신·읽음 처리 endpoint는 확정 전이므로 이번 범위에서는 구현하지 않는다.
- 알림 시간은 Mock 날짜를 기준으로 섹션을 결정하며, 추후 서버 timestamp와 현재 시간 기준으로 교체한다.
- 제공된 에셋 중 홈 섹션과 알림 아이콘에 필요한 이미지를 앱 Asset Catalog에 포함한다.
