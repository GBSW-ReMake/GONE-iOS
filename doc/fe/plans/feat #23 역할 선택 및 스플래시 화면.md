## 1. 목적 및 배경

앱을 실행하면 스플래시 화면을 먼저 표시하고, 학생과 선생님 중 로그인 역할을 선택하게 합니다. 로그인 화면에서 역할 선택 컨트롤을 제거해 사용자가 선택한 역할로 바로 로그인하도록 흐름을 단순화합니다.

## 2. 사용자 시나리오

```text
사용자가 앱을 실행한다
→ GONE 로고가 화면 중앙에 표시된 스플래시 화면을 확인한다
→ 로고가 축소되며 역할 선택 화면이 자연스럽게 나타난다
→ 학생 로그인 또는 선생님 로그인을 선택한다
→ 선택한 역할에 맞는 로그인 화면에서 아이디와 비밀번호를 입력한다
→ 로그인에 성공하면 선택한 역할의 홈 화면으로 이동한다
```

## 3. 화면 및 UX

- 스플래시 화면은 흰색 배경 중앙에 GONE 로고를 표시합니다. 로고를 축소하고 페이드 효과를 적용해 역할 선택 화면으로 전환합니다.
- 역할 선택 화면은 GONE 로고, 제목, 안내 문구, 사용자 일러스트, 학생·선생님 로그인 버튼을 표시합니다.
- 두 버튼은 44pt 이상 높이로 제공하며 VoiceOver 이동 안내를 포함합니다.
- 로그인 화면에서 역할 선택 세그먼트를 제거하고 선택한 `AccountRole`을 로그인 자격 증명에 사용합니다.
- 로그인 화면 상단에 로그인 유형을 다시 선택하는 뒤로 가기 버튼을 제공합니다.
- 로그인과 역할 선택 화면의 GONE 로고, 제목, 안내 문구 크기를 통일합니다.
- 회원가입을 닫으면 사용자가 선택한 역할의 로그인 화면으로 돌아옵니다.
- Reduce Motion에서는 축소 이동을 생략하고 페이드 전환을 제공합니다.

## 4. 데이터 및 아키텍처

```text
ContentView → SplashView → RoleSelectionView → LoginView(role: AccountRole)
→ LoginViewModel → LoginCredentials(role: AccountRole) → AppTabView(role: AccountRole)
```

- `ContentView`는 화면 전환 상태를 관리합니다.
- `SplashView`는 표시 완료 이벤트만 전달합니다.
- `RoleSelectionView`는 선택한 역할을 상위 화면으로 전달합니다.
- `LoginViewModel`은 입력 검증을 담당하며 역할을 변경하지 않습니다.

## 7. 특이 사항 / 기술 검토

- 스플래시 표시는 앱을 실행할 때마다 적용합니다. 최초 실행 여부는 저장하지 않습니다.
- iOS 시스템 Launch Screen은 유지하고, 스플래시는 앱 UI가 표시된 뒤 실행합니다.
- 실제 교사·학생 인증 API가 분리되어 있지 않으므로 기존 `AccountRole` 전달 범위만 변경합니다.
- 공통 문서인 `SENTENCE_REFINEMENT.md`는 기능 구현과 분리한 문서 커밋으로 남깁니다.
