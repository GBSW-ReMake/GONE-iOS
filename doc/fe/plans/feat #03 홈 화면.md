## 1. 목적 및 배경

학생이 앱에 진입했을 때 오늘의 학교생활 정보를 한 화면에서 빠르게 확인하고, 실습실·외출·스쿨캠핑 기능으로 자연스럽게 이동할 수 있는 홈 화면을 제공합니다.

Figma 홈 화면([노드 2:832](https://www.figma.com/design/l3MKhDJ6ciT7gfSvTpiYNI/%EA%B2%BD%EC%86%8C%EB%A7%88%EA%B3%A0-%EA%B4%80%EB%A6%AC%EC%8B%9C%EC%8A%A4%ED%85%9C?node-id=2-832))을 기준으로 사용자 요약, 오늘의 시간표·급식, 신청 현황과 5개 목적지의 하단 탭 바를 구현합니다.

## 2. 사용자 시나리오

```text
사용자가 로그인 완료 후 홈 탭에 진입한다
→ 날짜·인사말과 본인의 학적·상벌점·역할을 확인한다
→ 오늘 수업, 급식, 실습실·외출·스쿨캠핑 신청 현황을 확인한다
→ 하단 탭을 눌러 각 기능의 화면으로 이동한다
→ 데이터가 없거나 불러오기 실패 시 원인과 재시도 행동을 확인한다
```

## 3. 화면 및 UX

### 화면 구성

- 상단 헤더: 현재 날짜와 사용자 이름을 포함한 인사말
- 사용자 요약 카드: 학과·학년·반·번호, 상점·벌점·현재 점수, 역할 목록
- 오늘의 학교생활 카드: 현재 또는 다음 교시 강조, 교과목·장소·시간, 전체 시간표, 오늘의 급식 정보
- 신청 현황 카드: 실습실 신청, 외출 신청, 스쿨캠핑 예약의 요약·상태
- 하단 탭 바: `홈` / `실습실` / `외출` / `스쿨캠핑` / `설정`
- 제공 에셋: 실습실·외출·스쿨캠핑 카드에 각각 연결하며, 탭 아이콘 SVG도 원본 형태로 에셋 카탈로그에 등록

### 화면 전환 및 상태

- 탭 바는 `TabView` 기반으로 구성하며 홈을 기본 선택 탭으로 둡니다.
- 아직 구현하지 않는 탭 목적지는 라우팅과 접근성 레이블을 갖춘 빈 상태 화면으로 우선 제공합니다.
- 로딩: 카드별 진행 상태 또는 화면 초기 로딩 상태를 표시하고 중복 요청을 방지합니다.
- 빈 상태: 시간표·급식·신청 현황이 없을 때 정보 부재와 다음 행동을 명확히 안내합니다.
- 오류 상태: 네트워크·서버 오류 시 내용과 재시도 행동을 제공합니다.
- 화면은 스크롤 가능하게 구성하고, 하단 탭 바에 콘텐츠가 가려지지 않도록 안전 영역을 고려합니다.

### 접근성

- 탭마다 제목과 선택 상태를 VoiceOver로 전달합니다.
- 카드 내부의 상태(신청 완료·승인 대기·예약 완료)는 색상뿐 아니라 텍스트로 전달합니다.
- 모든 탭과 상호작용 요소는 최소 44pt 터치 영역을 확보합니다.
- Dynamic Type 확대와 다크 모드에서 텍스트 잘림·대비 부족·카드 레이아웃 깨짐이 없도록 검증합니다.

## 4. 데이터 및 아키텍처

### 데이터 흐름

```text
AppTabView
→ HomeView
→ HomeViewModel
→ FetchHomeDashboardUseCase
→ HomeDashboardRepository (protocol)
→ MockHomeDashboardRepository / RemoteHomeDashboardRepository
→ 홈 대시보드 API
```

- `AppTabView`: 5개 최상위 탭의 선택 상태와 각 화면의 진입점을 관리합니다.
- `HomeView`: 화면 표현과 사용자 입력 전달만 담당합니다.
- `HomeViewModel`: 홈 데이터, 로딩·빈·오류 상태 및 재시도 이벤트를 관리합니다.
- `FetchHomeDashboardUseCase`: 홈 화면에 필요한 데이터를 조합하는 비즈니스 규칙을 담당합니다.
- `HomeDashboardRepository`: 홈 데이터 접근을 추상화합니다.
- `HomeDashboard`: 사용자 요약, 시간표, 급식, 신청 현황 모델을 묶는 화면 전용 도메인 모델입니다.

### 초기 데이터 전략 및 결정 필요 항목

- API 계약 전에는 Figma에 표시된 데이터를 기반으로 한 `MockHomeDashboardRepository`를 사용합니다.
- 실제 API 연동 시 endpoint, 응답 DTO, 시간표·급식 갱신 기준, 상벌점·역할 권한, 신청 상태 코드의 확정이 필요합니다.
- 실제 로그인 사용자 정보가 아직 홈으로 전달되지 않으므로, 인증 완료 후 홈 진입 라우팅과 사용자 식별자 전달 방식은 별도 확인이 필요합니다.
- 카드 탭 시 상세 화면으로 이동하는 범위는 각 기능 화면의 구현 일정과 함께 확정합니다.

- [ ] 사용자 요약 카드와 오늘의 학교생활 카드를 구현한다.

- [ ] 미구현 탭의 빈 상태 화면과 홈 카드의 전환 규칙을 연결한다.

## 6. 완료 기준

- [ ] Figma 홈 화면의 정보 구조, 카드 우선순위, 탭 구성과 선택 상태가 구현된다.
- [ ] 홈 화면은 View·ViewModel·UseCase·Repository의 책임이 분리된 구조를 따른다.
- [ ] 제공된 이미지·아이콘은 원본 에셋을 사용하며 누락되지 않는다.
- [ ] 로딩·빈·오류·재시도 상태가 구현된다.
- [ ] 5개 탭을 전환할 수 있고, 홈 이외의 미구현 탭도 접근 가능한 빈 상태를 제공한다.
- [ ] 다크 모드, Dynamic Type, VoiceOver, 44pt 이상 터치 영역, 안전 영역을 검증한다.
- [ ] 단위 테스트·빌드·시뮬레이터 QA 결과를 기록한다.

## 7. 특이 사항 / 기술 검토

- 탭 바는 Figma의 커스텀 글래스 표현을 그대로 재구성하지 않고, iOS의 접근성·선택 상태·안전 영역을 제공하는 `TabView`를 우선 사용합니다. 세부 외형은 iOS 기본 동작을 훼손하지 않는 범위에서 조정합니다.
- Figma의 기기 상태 바와 홈 인디케이터는 앱 UI가 아니므로 구현하지 않습니다.
- 현재 작업 트리는 `feat/4-signup` 브랜치이며 `GONE 이미지` 폴더가 미추적 상태입니다. 계획 승인 후 GitHub 이슈를 만든 다음, 독립 홈 기능 브랜치에서 작업합니다.
- 실제 API 명세가 확정되기 전에는 네트워크 DTO·권한 정책·상태 코드를 임의로 추가하지 않습니다.
