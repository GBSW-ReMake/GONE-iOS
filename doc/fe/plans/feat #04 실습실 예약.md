## 1. 목적 및 배경

학생이 층별 실습실의 예약 가능 여부와 시설 정보를 확인하고, 사용 인원·명단·목적을 입력해 대여를 신청할 수 있도록 합니다.

대여 신청 완료 후에는 신청 상세 카드와 진행 상태를 보여 주며, 홈의 신청 현황에도 동일한 신청 상태가 반영됩니다.

## 2. 사용자 시나리오

```text
사용자가 하단 실습실 탭 또는 홈의 실습실 신청 카드를 누른다
→ 4층 / 3층 / 2층 탭에서 층별 실습실을 확인한다
→ 원하는 실습실 카드를 누르면 선택 테두리와 예약하기 버튼이 활성화된다
→ 예약하기를 누르고 대표자·사용 인원 명단·사용 목적을 입력한다
→ 필수 항목이 유효하면 대여 신청하기 버튼이 활성화된다
→ 신청을 완료하면 내 실습실 대여 완료 카드와 신청 상태를 확인한다
→ 홈 신청 현황에도 해당 실습실 신청 카드가 동기화되어 표시된다
```

## 3. 화면 및 UX

### 실습실 목록

- 상단: `실습실 대여`, 날짜형 제목, 4층 / 3층 / 2층 세그먼트 탭
- 4층: Figma 기준 5개 실습실 목록
  - NCS 응용 프로그래밍 실습실2 (최대 20명 · 빔프로젝터)
  - NCS 게임콘텐츠 제작 실습실1 (최대 20명 · 빔프로젝터)
  - SW 채움교실 (최대 16명 · 빔프로젝터)
  - LAB 6실 (최대 7명)
  - LAB 7실 (최대 7명)
- 3층·2층: 실제 데이터 연동 전에는 층과 시설 특성을 반영한 Mock 실습실 목록을 제공합니다.
- 실습실 카드는 번호, 이름, 수용 인원·시설, `예약 가능` 상태를 표시합니다.
- 선택한 카드에는 브랜드 블루 테두리를 표시합니다.
- 선택 전 `예약하기` CTA는 비활성 회색, 선택 후 선택 실습실 이름을 포함한 활성 CTA로 표시합니다.

### 실습실 신청 폼

- 상단: 뒤로가기와 `실습실 대여` 제목
- 선택 요약 카드: 층·실습실 이름·최대 인원·시설
- 입력 항목: 대표자, 사용 인원 명단, 사용 목적
- 사용 인원 명단에는 학번과 이름 입력 안내, 최대 인원·형식 안내를 제공합니다.
- 필수 입력값이 비어 있거나 최대 인원을 초과하면 `대여 신청하기` CTA는 비활성화됩니다.
- 입력 완료 후 CTA를 눌러 신청 완료 카드로 전환합니다.

### 실습실 대여 완료 카드

- 상단: `내 실습실 대여`와 `새 예약` 진입점
- 상태 카드: 예약 상태, 신청 번호, 실습실·층·날짜, 이용 시간, 대표자, 사용 인원, 사용 목적
- 진행 상태: 신청 완료 → 승인 대기 → 이용 가능
- `대여 취소`는 별도 확인 절차를 거쳐 처리합니다.
- 담당 교사 승인 후 이용 가능 상태가 되며 홈 신청 현황에도 갱신됨을 안내합니다.

### 홈 연동

- 홈의 실습실 신청 카드는 최신 `LabReservation` 상태와 실습실·이용 시간을 표시합니다.
- 홈 카드 탭 시 실습실 탭의 완료 카드 또는 목록 화면으로 이동합니다.
- 실습실 신청·취소·상태 변경은 단일 저장소를 통해 홈과 실습실 화면에 동시에 반영합니다.

### 접근성 및 상태

- 층 탭·실습실 카드·CTA는 최소 44pt 터치 영역을 확보합니다.
- 선택·예약 가능·승인 대기·이용 가능은 색상뿐 아니라 텍스트와 VoiceOver 상태로 전달합니다.
- 목록 로딩, 빈 층, 예약 불가, 신청 실패 및 재시도 상태를 제공합니다.
- Dynamic Type 확대 시 긴 실습실 이름·명단·사용 목적이 잘리지 않도록 스크롤과 줄바꿈을 지원합니다.

## 4. 데이터 및 아키텍처

### 데이터 흐름

```text
AppTabView / HomeView
→ LabRoomListView / LabReservationFormView / LabReservationDetailView
→ LabReservationViewModel
→ FetchLabRoomsUseCase / SubmitLabReservationUseCase / FetchCurrentLabReservationUseCase
→ LabReservationRepository (protocol)
→ MockLabReservationRepository / RemoteLabReservationRepository
→ 실습실·예약 API
```

- `LabRoom`: 식별자, 층, 이름, 최대 인원, 시설, 예약 가능 상태를 표현합니다.
- `LabReservationDraft`: 선택 실습실, 대표자, 명단, 사용 목적, 이용 시간을 임시 관리합니다.
- `LabReservation`: 신청 번호, 상태, 이용 시간, 신청 상세를 표현합니다.
- `LabReservationRepository`: 층별 목록·현재 예약·신청·취소의 데이터 접근을 추상화합니다.
- `HomeDashboardRepository`와 실습실 Repository는 현재 예약 상태를 공유할 수 있는 단일 소스 또는 이벤트 갱신 전략을 사용합니다.

### 외부 의존성 및 결정 필요 항목

- 실제 층별 실습실 목록, 시설, 정원, 예약 가능 시간 및 중복 예약 정책
- 대표자 자동 설정 규칙과 사용 인원 명단 형식·최대 인원 검증 규칙
- 신청 번호 생성, 교사 승인·반려·취소 API 및 상태 코드
- 홈 대시보드 API와 실습실 최신 예약 상태의 동기화 계약

API 계약 전에는 Figma에 표시된 4층 정보와 3·2층 Mock 데이터를 사용하며, 실제 DTO·권한 정책은 임의로 추가하지 않습니다.

## 7. 특이 사항 / 기술 검토

- 하단 실습실 탭은 목록, 신청 폼은 `NavigationStack` push, 완료 카드는 실습실 탭의 상태 화면으로 구성합니다.
- 실습실 선택은 리스트 행이 아닌 카드 자체를 버튼으로 처리해 충분한 터치 영역과 선택 상태를 제공합니다.
- 홈 화면은 예약 상태의 소비자이며, 예약 생성·취소 비즈니스 로직은 실습실 UseCase에만 둡니다.
- Figma MCP Starter 호출 한도에 도달해 신청 폼·완료 카드의 세부 값은 제공된 시안을 기준으로 기록했습니다. 구현 전 사용 가능한 Figma 컨텍스트 또는 시안으로 재확인합니다.
