## 1. 목적 및 배경

다크 모드에서도 라이트 모드와 동일한 GONE 색상·배경·카드 표현을 유지하도록 앱의 표시 모드를 라이트로 고정합니다.

또한 외출 탭을 단순 placeholder에서 외출 신청, 승인 대기, 출발 가능, 외출 중, 복귀 요청까지 이어지는 상태 기반 기능으로 확장합니다. 사용자는 외출 신청 정보를 작성하고, 승인 후 정해진 시간에 맞춰 1.5초 길게 눌러 외출을 시작하거나 복귀를 완료합니다.

## 2. 사용자 시나리오

```text
사용자가 외출 탭에 진입한다
→ 외출 목적과 날짜·출발·복귀 시간을 작성해 신청한다
→ 신청 완료 카드를 통해 승인 대기 상태를 확인하거나 신청을 취소한다
→ 승인 후 출발 20분 전까지 대기 상태와 남은 시간을 확인한다
→ 출발 가능 시간이 되면 외출 버튼을 1.5초 길게 눌러 외출을 시작한다
→ 외출 중에는 위치 공유 상태·남은 시간·파동 애니메이션을 확인한다
→ 학교 주변 복귀 가능 범위에 들어오면 복귀 버튼을 1.5초 길게 눌러 외출을 종료한다
```

## 3. 화면 및 UX

### 고정 테마

- `GONEApp` 루트에 `.preferredColorScheme(.light)`를 적용해 시스템 다크 모드와 관계없이 라이트 표현을 유지합니다.
- 화면 배경·카드·입력 필드의 시스템 동적 색상 사용 위치를 고정 GONE 표면 색상 토큰으로 전환합니다.
- 텍스트·강조·오류·상태 색상은 기존 GONE 토큰을 유지하고, 외출 상태별 색상(대기 회색, 출발 파랑, 외출 중 주황, 복귀 빨강)을 추가합니다.

### 외출 화면

- 기본 화면: 날짜 강조 제목, 외출 안내, 외출 신청 CTA, 하단 외출 탭 선택 상태를 표시합니다.
- 신청 폼: 외출 날짜, 출발 시간, 복귀 시간, 외출 사유를 입력합니다. 복귀 시간은 출발 시간보다 늦어야 하며 모든 항목이 유효할 때만 제출합니다.
- 신청 완료: 승인 대기 배지, 신청 번호, 외출 시간·사유, 진행 단계, 신청 취소·재신청을 제공합니다.
- 승인 대기/출발 가능/외출 중/복귀:
  - 상태 제목과 남은 시간 또는 복귀 시간을 중심 정렬해 표시합니다.
  - 원형 CTA는 현재 상태에 따라 `대기`/`외출`/`외출 중`/`복귀`로 바뀝니다.
  - 외출과 복귀 CTA는 1.5초 길게 눌러야 완료되며, 진행률·햅틱 피드백·취소 가능 상태를 제공합니다.
  - 외출 중에는 원형 CTA를 중심으로 확산·소멸하는 파동 애니메이션을 표시하고 위치 공유 중임을 텍스트로 알립니다.

### 접근성 및 안전

- 길게 누르기는 VoiceOver에서 `외출 시작`/`복귀 완료` 사용자 액션으로도 수행 가능하게 합니다.
- 상태 색상만으로 구분하지 않고 제목·남은 시간·설명으로 상태를 전달합니다.
- 위치 권한 거부·제한·오류 시 외출 진행 가능 여부와 재시도 방법을 안내합니다.
- 위치 공유는 외출 중에만 시작하고 복귀·취소·만료 시 즉시 중지하는 것을 완료 기준으로 합니다.

## 4. 데이터 및 아키텍처

### 데이터 흐름

```text
OutingView / OutingRequestFormView
→ OutingViewModel
→ SubmitOutingRequestUseCase / StartOutingUseCase / CompleteReturnUseCase
→ OutingRepository (protocol) / LocationSharingRepository (protocol)
→ MockOutingRepository / MockLocationSharingRepository
```

- `Outing`: 외출 날짜·출발·복귀 시간·사유·신청 번호·승인 상태를 표현하는 도메인 모델입니다.
- `OutingStatus`: `idle`, `pendingApproval`, `waitingToStart`, `readyToLeave`, `outing`, `readyToReturn`, `completed` 상태를 분리합니다.
- `OutingViewModel`: 화면 상태, 폼 유효성, 카운트다운, 길게 누르기 진행률, 오류·로딩 상태를 담당합니다.
- `LocationSharingRepository`: Core Location 권한과 위치 공유 세션을 추상화합니다. 초기 구현은 실제 전송 대신 Mock 상태로 검증합니다.
- `OutingRepository`: 신청·취소·승인·외출 시작·복귀 처리 API 계약이 확정되면 실제 구현으로 교체합니다.

### 외부 의존성 및 결정 필요 항목

- Figma MCP 호출 한도로 원본 외출 프레임을 직접 조회하지 못했습니다. 제공된 2~9번 화면을 구현 기준으로 하며, 한도 해제 뒤 원본 프레임과 대조합니다.
- 외출 신청·승인·취소·시작·복귀 API endpoint와 DTO
- 선도부 위치 수신 방식, 위치 갱신 주기, 보관 기간, 접근 권한, 개인정보 동의 문구
- 학교 복귀 판정 지오펜스 좌표·반경과 GPS 오차 허용 범위
- 백그라운드 위치 권한 및 App Store 개인정보 고지·심사 대응

## 5. 작업 목록

- [ ] 앱과 공용 표면 색상을 라이트 고정 테마로 정리한다.
- [ ] 외출 Domain Model, Repository protocol, Mock repository를 추가한다.
- [ ] 외출 상태 머신과 신청 폼 유효성·카운트다운을 `OutingViewModel`에 구현한다.
- [ ] 외출 기본·신청 폼·신청 완료 카드·상태 화면을 구현한다.
- [ ] 1.5초 길게 누르기 CTA와 햅틱·진행률 표현을 구현한다.
- [ ] 외출 중 위치 공유 파동 애니메이션과 권한 안내를 구현한다.
- [ ] 외출 탭을 실제 화면으로 연결하고 단위 테스트·QA를 진행한다.

## 6. 완료 기준

- [ ] 시스템 다크 모드에서도 앱의 배경·카드·입력 필드·텍스트가 라이트 기준 고정 색상으로 표시된다.
- [ ] 외출 신청 폼은 유효하지 않은 시간·빈 사유의 제출을 막는다.
- [ ] 신청 완료, 승인 대기, 출발 가능, 외출 중, 복귀 가능 상태가 상태 모델에 따라 전환된다.
- [ ] 외출·복귀 동작은 1.5초 길게 눌러야 실행되고, 진행률·햅틱·접근성 대안이 제공된다.
- [ ] 외출 중 파동 애니메이션과 위치 공유 상태가 표시되며, 종료 시 공유 세션이 중지된다.
- [ ] ViewModel 단위 테스트와 시뮬레이터 QA 결과가 기록된다.

## 7. 기술 검토

- 실제 위치 공유 및 지오펜스는 개인정보와 백그라운드 권한을 수반하므로 API·운영 정책 확정 전에는 Mock 흐름과 권한 UX까지만 제공합니다.
- 기존 미커밋 에셋·홈 화면 변경은 이번 기능에 포함하지 않습니다.
- 개발자 요청에 따라 계획서 작성 직후 이슈·브랜치·구현을 진행합니다.
