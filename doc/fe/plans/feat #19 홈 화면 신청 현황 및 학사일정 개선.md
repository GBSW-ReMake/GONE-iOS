## 1. 목적 및 배경

홈 탭의 사용자 요약 카드에서 더 이상 제공하지 않는 **상점** 정보를 제거합니다.

또한 신청 현황은 현재 실습실 신청만 카드에서 실제 흐름을 확인할 수 있어, 외출 신청과 스쿨캠핑 예약도 신청 여부에 따라 적절한 화면으로 연결할 수 있도록 확장합니다.

급식 카드 상단에는 선택한 달의 학사일정을 세로 카드 목록으로 표시하는 UI를 추가합니다. 이번 작업은 UI와 목 데이터까지만 구현하며, 백엔드 API 연동은 포함하지 않습니다.

## 2. 사용자 시나리오

```text
사용자가 홈 탭에 진입한다
→ 학과·학적 정보, 벌점 및 현재 점수를 확인한다
→ 오늘 시간표 다음으로 해당 월의 학사일정을 세로 카드 목록에서 확인한다
→ 우측 상단 이전/다음 달 버튼으로 표시 월을 변경한다
→ 급식 정보를 확인한다
→ 신청 현황에서 실습실·외출·스쿨캠핑 카드를 선택한다
→ 신청 내역이 있으면 각 기능의 신청/예약 상세 또는 현황 화면으로 이동한다
→ 신청 내역이 없으면 해당 기능의 신규 신청 화면으로 이동한다
```

## 3. 화면 및 UX

### 화면 구성

- 사용자 요약 카드
  - `상점` 항목을 제거하고 `벌점`, `현재 점수`만 표시합니다.
  - 모델의 상점 데이터는 다른 사용처가 없다면 제거 여부를 구현 시 별도 확인합니다.
- 학사일정 섹션
  - 위치: 오늘 시간표와 오늘 급식 사이.
  - 제목: `학사일정`과 선택 중인 `yyyy년 M월`을 표시합니다.
  - 월 이동: 섹션 오른쪽 상단에 이전/다음 버튼(`chevron.left`, `chevron.right`)을 둡니다.
  - 일정 목록: 날짜, 요일/일정명, 일정 유형을 포함한 세로 카드뷰를 표시합니다. 제공 이미지처럼 날짜와 명칭이 빠르게 구분되도록 구성합니다.
  - 월에 일정이 없으면 빈 상태 메시지를 표시합니다.
- 신청 현황 카드
  - 실습실 신청, 외출 신청, 스쿨캠핑 예약 모두 탭 동작을 제공합니다.
  - 신청 내역이 있는 경우: 각 기능의 신청 현황/상세 화면으로 이동합니다.
  - 신청 내역이 없는 경우: 각 기능의 신규 신청 화면으로 이동합니다.
  - 상태는 색상과 텍스트를 함께 표시하며, 모든 카드에 화살표와 접근성 레이블을 제공합니다.

### 상태 및 접근성

- 학사일정: 정상, 월별 빈 상태, 추후 API 연동 시 로딩·오류 상태를 준비합니다.
- 신청 현황: 신청 있음/없음 상태를 명확히 구분합니다. 미신청 상태의 문구는 `신청하기` 등 행동을 안내하는 표현으로 확정합니다.
- 월 이동 및 신청 현황 카드는 최소 44pt 터치 영역을 확보합니다.
- VoiceOver에서 선택된 월, 일정 날짜·제목, 신청 상태와 이동 목적지를 읽을 수 있게 합니다.
- Dynamic Type, 다크 모드, 작은 화면에서 카드 내용이 잘리지 않도록 QA합니다.

## 4. 데이터 및 아키텍처

### 데이터 흐름

```text
AppTabView
→ HomeView
→ HomeViewModel
→ FetchHomeDashboardUseCase
→ HomeDashboardRepository
→ MockHomeDashboardRepository (이번 작업) / RemoteHomeDashboardRepository (향후)
```

- `HomeDashboard`에 학사일정 목록을 위한 화면 도메인 모델을 추가합니다.
- `HomeViewModel`은 현재 표시 월 및 월 이동 이벤트를 관리합니다. 일정 데이터는 화면 로직이 아닌 도메인 데이터로 필터링합니다.
- `HomeView`는 학사일정 카드 UI와 월 이동 입력, 신청 현황 카드의 이동 이벤트만 전달합니다.
- `AppTabView` 또는 기능별 라우터가 실습실·외출·스쿨캠핑의 "내역 있음/없음" 목적지 결정을 전달합니다. 기존 실습실의 `LabReservation?` 패턴을 재사용 가능한 방식으로 확장할지 구현 전 확인합니다.

### API 연동 전 결정 필요 항목

- 학사일정 API의 월 조회 파라미터, 날짜 형식, 일정 유형/정렬 규칙, 휴업일 표기 규칙은 백엔드 명세 확정 후 연결합니다.
- 외출 신청 및 스쿨캠핑 예약의 "신청 있음" 기준과 상세 진입 화면의 최종 목적지는 기존 기능의 화면 구조를 확인해 확정합니다.
- 현재 목 데이터에는 예시로 8월의 휴업일·개학식·광복절 등 이미지와 유사한 형태의 일정만 사용합니다. 실제 학사일정으로 간주하지 않습니다.

## 5. 작업 목록

- [ ] 현재 홈·외출·스쿨캠핑·실습실 라우팅과 신청 상태 모델을 확인한다.
- [ ] 사용자 요약 카드에서 상점을 제거하고 관련 모델 영향 범위를 점검한다.
- [ ] 학사일정 도메인 모델, 목 데이터, 월 선택 상태와 UseCase/Repository 흐름을 추가한다.
- [ ] 오늘 시간표와 오늘 급식 사이에 월 이동 가능한 세로 학사일정 카드 UI를 구현한다.
- [ ] 외출·스쿨캠핑 신청 현황 카드에 신청 있음/없음에 따른 이동 규칙을 연결한다.
- [ ] ViewModel 단위 테스트와 필요한 라우팅 테스트를 추가한다.
- [ ] 정상·빈 상태·월 이동·각 신청 분기·다크 모드·Dynamic Type·VoiceOver QA를 수행하고 이슈 보고서를 작성한다.

## 6. 완료 기준

- [ ] 홈 사용자 요약 카드에 상점이 표시되지 않는다.
- [ ] 학사일정이 시간표와 급식 사이에 세로 카드 목록으로 표시된다.
- [ ] 이전/다음 월 버튼으로 표시 월과 해당 월 일정 목록을 변경할 수 있다.
- [ ] 일정이 없는 월에는 이해 가능한 빈 상태를 표시한다.
- [ ] 실습실·외출·스쿨캠핑 카드 모두 신청 여부에 맞는 화면으로 이동한다.
- [ ] View·ViewModel·UseCase·Repository·Model 책임을 기존 MVVM/Clean Architecture 구조에 맞게 분리한다.
- [ ] 빌드와 자동 테스트를 통과하고, 정의된 수동 QA 결과를 기록한다.

## 7. 특이 사항 / 기술 검토

- 사용자 요청 범위는 "UI만"이므로 학사일정의 실제 네트워크 요청, DTO, 캐시·갱신 정책은 구현하지 않습니다. API 교체가 쉽도록 Repository의 목 구현에만 예시 데이터를 둡니다.
- 월 이동은 API 연동 전에도 동일한 UX를 검증할 수 있도록 월별 목 데이터를 사용합니다. 선택 월의 기본값은 목 데이터가 존재하는 월로 둘지, 실제 현재 월로 둘지는 구현 시 기존 테스트의 날짜 의존성을 피하는 방향으로 결정합니다.
- 신청 현황의 "신청 있음" 목적지가 기능별로 다를 수 있습니다. 외출·스쿨캠핑 화면의 현 구조를 확인한 뒤, 상세 화면이 없으면 해당 기능 탭의 신청 현황 섹션으로 이동하도록 최소 범위로 연결합니다.
- 상점 데이터는 화면에서만 제외합니다. 사용자 프로필 API/다른 화면의 계약 변경은 이번 범위에 포함하지 않습니다.
