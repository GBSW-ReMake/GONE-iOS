# 스쿨캠핑 예약 UI 및 신청 플로우 계획서

> **작성일**: 2026-08-06
> **작업 번호**: #07
> **관련 이슈**: [#14](https://github.com/GBSW-ReMake/GONE-iOS/issues/14)
> **대상 브랜치**: `feat/14-school-camping-reservation`

---

## 1. 목표

하단 **스쿨캠핑** 탭을 실제 예약 흐름으로 교체합니다.

1. 월간 달력에서 예약 가능한 날짜를 선택합니다.
2. 선택한 날짜의 예약 폼으로 이동해 담당 선생님과 참여 명단을 확인·작성합니다.
3. 신청이 완료되면 예약 완료 카드에서 날짜, 담당 선생님, 인원, 대표 학생, 참여 명단과 취소 동작을 확인합니다.

## 2. 시안 해석 및 화면 범위

첨부 시안의 흐름을 기준으로 다음 세 화면을 구현합니다.

| 화면 | 주요 UI·동작 |
|---|---|
| 스쿨캠핑 달력 | 월 이동, 예약 가능·예약 불가·내 예약 상태, 날짜 선택, `내 예약` 진입 |
| 예약 신청 폼 | 선택 날짜 표시, 담당 선생님, 최대 8명 참여 명단, 인원 추가·삭제, 유효성 검증 CTA |
| 예약 신청 완료 | 상태 배지, 날짜, 담당 선생님·인원·대표 학생 행, 참여 명단 확인/수정 행, 예약 취소, 달력 보기 |

## 3. 구현 설계

### 아키텍처

- `SchoolCampingReservation`, `SchoolCampingReservationDraft`, `CampingDateAvailability`, `CampingParticipant` 도메인 모델을 둡니다.
- `SchoolCampingRepository`로 월간 가능 날짜·현재 예약·신청·취소를 추상화합니다.
- API 계약 전에는 `MockSchoolCampingRepository`가 월간 상태와 메모리 기반 예약을 제공합니다.
- `SchoolCampingViewModel`이 선택 날짜, 폼 상태, 예약 상태와 오류 메시지를 관리합니다.
- `SchoolCampingView`는 달력·폼·완료 카드를 화면 상태에 따라 표시하며 비즈니스 로직을 직접 갖지 않습니다.

### 예약 규칙 (Mock 1차 범위)

- 현재 표시 월의 날짜만 선택하며, `예약 가능` 상태인 날짜만 폼으로 이동합니다.
- 내 예약은 한 건으로 제한합니다. 예약 후 해당 날짜는 `내 예약` 상태로 즉시 갱신합니다.
- 참여 인원은 대표 학생을 포함해 1~8명입니다.
- 대표 학생은 현재 로그인 Mock 사용자(`3206 김은찬`)로 기본 입력합니다.
- 담당 선생님은 시안의 `박00 선생님`을 Mock 값으로 표시합니다. 실제 교사 선택·배정은 API 계약 후 확장합니다.
- 신청 CTA는 날짜·참여 명단이 유효할 때만 활성화됩니다.

### UI 원칙

- 기존 `GONETheme`, `GONEPrimaryButton`, 하단 탭바와 고정 라이트 테마를 재사용합니다.
- 달력은 `LazyVGrid` 기반으로 구성하고, 예약 가능/불가/내 예약을 텍스트와 색만이 아닌 범례 및 접근성 레이블로 구분합니다.
- 예약 폼은 키보드 외부 탭 시 포커스를 해제하며, 긴 참여 명단은 스크롤 가능하게 처리합니다.
- 완료 카드는 실습실·외출 카드의 좌측 레이블/우측 값 행과 취소 버튼 크기를 재사용해 화면 간 일관성을 유지합니다.

## 4. 구현 단위 및 커밋 계획

| 순서 | 작업 | 예정 커밋 |
|---|---|---|
| 1 | 도메인 모델, Repository 프로토콜, Mock Repository, ViewModel 상태 전환 | `feat: 스쿨캠핑 예약 도메인 추가` |
| 2 | 월간 달력 UI와 날짜 상태·선택 네비게이션 | `feat: 스쿨캠핑 예약 달력 구현` |
| 3 | 예약 폼, 참여 명단 검증, 완료 카드·취소·달력 갱신 | `feat: 스쿨캠핑 신청 플로우 구현` |
| 4 | 빌드 QA, 계획/최종 보고서 갱신 | `docs: 스쿨캠핑 예약 QA 보고서 추가` |

## 5. 검증 계획

- `xcodebuild build`로 Debug 컴파일을 확인합니다.
- 예약 가능·불가·내 예약 날짜의 선택 가능 여부와 달력 범례를 확인합니다.
- 참여 인원 추가/삭제, 1명 미만·8명 초과 방지, CTA 활성/비활성을 확인합니다.
- 신청 후 완료 카드와 달력의 내 예약 상태 갱신, 취소 후 초기 상태 복귀를 확인합니다.
- 실기기에서 Dynamic Type, VoiceOver 레이블, 키보드 해제 동작을 검토합니다.

## 6. 범위 밖 및 후속 작업

- 실제 예약 API, 교사 배정 API, 다른 학생 검색·중복 인원 검증은 서버 계약 후 연결합니다.
- 다중 예약, 승인/반려, 알림, 실시간 정원 동기화는 이번 UI·Mock 범위에서 제외합니다.

## 7. 검토 요청 사항

- 담당 선생님은 1차에서 시안처럼 자동 표시(Mock)하고, 실제 선택 UI는 API 연동 단계로 미루는 방향입니다.
- 참여자는 `학번 + 이름` 한 줄 입력으로 추가하며 최대 8명으로 제한합니다.
- 위 범위와 4개 커밋 단위가 맞으면 이슈 생성과 브랜치 분기 후 개발을 시작합니다.
